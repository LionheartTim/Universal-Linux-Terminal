# Typed Combination Engine (v0.3.2-alpha)

## Architecture

`composition_engine.py` is a GUI-free layer. Each `Subject(kind, value)` validates
an object such as a `SelectedApp`, `Volume`, existing file/folder, systemd unit,
Podman container name, network interface or host. `CompositionEngine` stores a
**draft selection context**. Each `Rule` declares a stable key, its required
subject kinds, a tool dependency, a risk level (`read` or `changes`), a guard and
a function that creates a `core.Command` (argv list, not shell source text).

`default_engine()` registers the reviewed built-in rules. GTK drives it by
selecting objects, showing `suggestions()`, and requesting `compose(rule_id)`.
The final `Command` is passed to the unchanged staging logic; it is never run
inside the engine. Even the command-preview line is generated by `shlex.join`.

## Adding a new reviewed rule

```python
from composition_engine import Rule, Subject, default_engine
from core import Command

engine = default_engine()
engine.register(Rule(
    key='host.example', title='Show selected host',
    description='Read-only example', required=('host',), tool='echo',
    factory=lambda selections: (
        Command('Show host', ['echo', selections['host'].value], ''), ''),
    risk='read',
))
engine.choose(Subject('host', 'example.org'))
command, explanation = engine.compose('host.example')
```

**Safety obligations for contributors:**

- Review the command and its exact argument schema; reject unsupported versions
  or missing dependencies. Do not infer a safe command from a similar name.
- Use argv arrays, not `shell=True` or a string interpreted as shell code.
- No auto-running tools for introspection or changing the system. `--help`,
  completion and man pages are not complete machine-checkable contracts.
- Distinguish read-only from permissions/system changes and destructive tasks.
  A `read` rule is checked against `Command.changes=True` as a basic guard,
  but **this does not prove an arbitrary command is actually safe**.
- Validate each selected subject against actual filesystem or platform state;
  don't automatically assume a target partition or package manager.
- For multiple dependent system changes, create a *step-by-step plan*, not
  an opaque `cmd1 && cmd2`. Require explicit approval before individual actions.
- Use pure-unit tests with invalid inputs, spaces, quoting and absent tools.
  Then perform GTK/VTE UI checks on each target distro/desktop.
- Translate UI strings via `i18n.tr` only; never translate argv values.

## Coverage and limitations

This is a **first version of the engine**, with read-only families and the
existing app+disk+folder access proposal. It does **not** cover all command
combinations, Shell aliases, function definitions, every package backend,
Steam's internal storage settings, arbitrary pipelines or destructive disk
operations. The regular terminal remains fully usable even when no recipe is
registered for a discovered command. The engine is designed for future
package-manager adapters and richer multi-step suggestions.
